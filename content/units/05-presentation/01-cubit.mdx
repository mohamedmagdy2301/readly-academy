<Note kind="info" title="الدرس ده الخريطة">

الدرس ده نظرة سريعة على الـ Cubit وأشهر مشاكله في مكان واحد. الطريق كامل بالتفصيل في [وحدة الـ State management](/course/state-management/): من أول `emit` لحد كل أنواع الـ Cubit، والـ HydratedCubit، والـ Bloc بالـ transformers، وامتى تستخدم ده وده، ومقارنتهم بـ Provider وRiverpod وGetX وغيرهم.

</Note>

<Analogy title="لوحة المطار">

final class LibraryLoading extends LibraryState {

  const LibraryError(this.failure);
  final Failure failure;

</CodeBlock>

<CodeBlock label="الـ Cubit">

```dart
class LibraryCubit extends Cubit<LibraryState> {
  LibraryCubit(this._getLibrary) : super(const LibraryLoading());

  final GetLibrary _getLibrary;

  Future<void> load() async {
    emit(const LibraryLoading());
    final result = await _getLibrary();
    emit(switch (result) {
      Success(:final value) => LibraryLoaded(value),
      Err(:final failure) => LibraryError(failure),
    });
  }
}
```

</CodeBlock>

<CodeBlock label="الـ UI">

```dart
BlocProvider(
  create: (_) => getIt<LibraryCubit>()..load(),
  child: BlocBuilder<LibraryCubit, LibraryState>(
    builder: (context, state) => switch (state) {
      LibraryLoading() => const Center(child: CircularProgressIndicator()),
      LibraryLoaded(:final books) => BookList(books: books),
      LibraryError(:final failure) => ErrorView(
          message: failure.localized(AppLocalizations.of(context)!),
          onRetry: context.read<LibraryCubit>().load,
        ),
    },
  ),
)
```

</CodeBlock>

| الـ widget | بيعمل إيه |
| --- | --- |
| `BlocProvider` | بيعمل الـ Cubit وبيقفله لما الـ widget يتشال |
| `BlocBuilder` | بيعيد رسم الـ UI مع كل state جديدة |
| `BlocListener` | بينفّذ حاجة مرة واحدة مع كل state (snackbar، navigation) من غير ما يرسم |

| `context.read` | يجيب الـ Cubit عشان تنادي method، من غير ما تسمع على التغييرات |

### الـ side effects مكانها BlocListener

الـ `build` ممكن يتنادى كذا مرة لنفس الـ state (مثلًا لما الكيبورد يفتح). لو حطيت navigation أو snackbar جواه، هيتكرروا:

<CodeBlock label="مرة واحدة بس">

```dart
BlocListener<AddBookCubit, AddBookState>(
  listenWhen: (prev, curr) => curr is AddBookSaved,
  listener: (context, state) => context.pop(),
  child: const AddBookForm(),
)
```

</CodeBlock>

### البحث: debounce وتجاهل النتايج القديمة

<CodeBlock label="debounce + request id">

```dart
class CatalogSearchCubit extends Cubit<CatalogSearchState> {
  CatalogSearchCubit(this._searchBooks) : super(const SearchIdle());

  final SearchBooks _searchBooks;
  Timer? _debounce;
  int _latestRequest = 0;

  void queryChanged(String input) {
    _debounce?.cancel();
    final query = input.trim();
    if (query.length < 2) {
      _latestRequest++;            // any in-flight result becomes stale
      emit(const SearchIdle());
      return;
    }
    _debounce = Timer(const Duration(milliseconds: 350), () => _search(query));
  }

  Future<void> _search(String query) async {
    final requestId = ++_latestRequest;
    emit(const SearchLoading());
    final result = await _searchBooks(SearchParams(query: query));
    if (isClosed || requestId != _latestRequest) return; // stale
    emit(switch (result) {
      Success(:final value) => SearchLoaded(value),
      Err(:final failure) => SearchError(failure),
    });
  }

  @override
  Future<void> close() {
    _debounce?.cancel();
    return super.close();
  }
}
```

</CodeBlock>

- <b>الـ debounce:</b> بيستنى 350ms من آخر حرف قبل ما يبحث، فبدل 7 طلبات لـ «flutter» بيبقى طلب واحد.
- <b>الـ request id:</b> لو طلب «flu» البطيء رجع بعد طلب «flutter»، الـ id بتاعه هيبقى قديم فيتجاهل.
- <b>الـ isClosed:</b> لو المستخدم قفل الشاشة والطلب لسه راجع، الـ emit بعد القفل بيرمي error.

### refresh من غير ما تمسح البيانات

المستخدم في المكتبة وسحب الليست لتحت عشان يحدّثها. لو الـ refresh نادى `load()`، أول سطر فيها `emit(const LibraryLoading())`، فالكتب بتختفي ويظهر spinner في نص الشاشة. ولو النت فاصل، `LibraryError` بيغطي الشاشة كلها، والكتب اللي كانت قدامه من ثانية راحت.

السبب إن كل state لوحدها: يا بيانات، يا loading، يا error. ومفيش state تقول «عندي بيانات وبحدّثها» ولا «عندي بيانات والتحديث فشل». والاتنين دول مش states جديدة، دول <b>حقول جوه LibraryLoaded</b>:

<CodeBlock label="LibraryLoaded وهو بيكبر">

```dart
final class LibraryLoaded extends LibraryState {
  const LibraryLoaded(this.books, {this.isRefreshing = false, this.refreshFailure});
  final List<Book> books;
  final bool isRefreshing;
  final Failure? refreshFailure;

  // refreshFailure is not "?? this": leaving it out clears it
  LibraryLoaded copyWith({List<Book>? books, bool? isRefreshing, Failure? refreshFailure}) =>
      LibraryLoaded(
        books ?? this.books,
        isRefreshing: isRefreshing ?? this.isRefreshing,
        refreshFailure: refreshFailure,
      );
}
```

</CodeBlock>

<CodeBlock label="refresh في الـ LibraryCubit">

```dart
Future<void> refresh() async {
  final current = state;
  if (current is! LibraryLoaded) return load(); // nothing on screen yet
  if (current.isRefreshing) return;            // one refresh at a time
  emit(current.copyWith(isRefreshing: true));   // the books stay
  final result = await _getLibrary();
  if (isClosed) return;
  emit(switch (result) {
    Success(:final value) => LibraryLoaded(value),
    Err(:final failure) => current.copyWith(refreshFailure: failure), // old list stays
  });
}
```

</CodeBlock>

<CodeBlock label="الـ UI: pull-to-refresh وsnackbar">

```dart
BlocListener<LibraryCubit, LibraryState>(
  listenWhen: (_, curr) => curr is LibraryLoaded && curr.refreshFailure != null,
  listener: (context, state) {
    final failure = (state as LibraryLoaded).refreshFailure!;
    ScaffoldMessenger.of(context).showSnackBar(SnackBar(
      content: Text(failure.localized(AppLocalizations.of(context)!)),
    ));
  },
  child: BlocBuilder<LibraryCubit, LibraryState>(
    builder: (context, state) => switch (state) {
      LibraryLoading() => const Center(child: CircularProgressIndicator()),
      LibraryLoaded(:final books) => RefreshIndicator(
          onRefresh: context.read<LibraryCubit>().refresh,
          child: BookList(books: books),
        ),
      LibraryError(:final failure) => ErrorView(
          message: failure.localized(AppLocalizations.of(context)!),
          onRetry: context.read<LibraryCubit>().load,
        ),
    },
  ),
)

// the same refresh from an AppBar button
BlocSelector<LibraryCubit, LibraryState, bool>(
  selector: (state) => state is LibraryLoaded && state.isRefreshing,
  builder: (context, refreshing) => IconButton(
    onPressed: refreshing ? null : context.read<LibraryCubit>().refresh,
    icon: const Icon(Icons.refresh),
  ),
)
```

</CodeBlock>

- <b>الـ RefreshIndicator:</b> بياخد function بترجّع Future، وبيعرض الـ spinner بتاعه فوق الليست لحد ما الـ Future يخلص. فالـ `refresh` لازم تستنى الطلب، مش ترجع على طول.
- <b>الـ isRefreshing:</b> الـ pull مش محتاجه عشان الـ RefreshIndicator بيعرض الـ spinner لوحده. بس أي refresh تاني محتاجه، زي الزرار اللي في الـ AppBar: بيتقفل طول ما في refresh شغال. وهو كمان اللي بيمنع refresh تاني يبدأ والأول لسه ماخلصش.
- <b>الـ BlocSelector:</b> بيختار قيمة واحدة من الـ state، وبيعيد رسم الزرار بس لما القيمة دي تتغير، مش مع كل state.
- <b>الـ refreshFailure بيتمسح لوحده:</b> الـ copyWith مابيعملش `?? this` للـ failure، فأي emit بعده بيمسحه. والـ snackbar في BlocListener، زي أول جزء في المستوى ده، فبيظهر مرة واحدة بس مهما الشاشة اتعاد رسمها.
- <b>الكود القديم ماتكسرش:</b> `books` لسه positional، فـ `LibraryLoaded(value)` في `load()` و`LibraryLoaded(books)` في `watch()` شغالين زي ما هما.

البيانات اللي ظاهرة مابتتمسحش عشان طلب جديد فشل: الـ loading والـ error بتوعه حقول جوه الـ Loaded state، مش states لوحدهم.


</Level>

<Level n="4" title="قرارات الـ senior">

- <b>Cubit ولا Bloc؟</b> الـ Cubit أبسط وكفاية لأغلب الشاشات. الـ Bloc مفيد لما تحتاج تتبع كل event، أو transformers جاهزة للـ concurrency. اللي بيفرق مش الأداة، اللي بيفرق إنك تحل الـ race conditions بنمط واضح ومتستّ.
- <b>التواصل بين Cubitين:</b> ماتخليش Cubit يمسك reference لـ Cubit تاني. خليهم الاتنين يسمعوا على stream من نفس الـ repository. مثلًا LibraryCubit وHomeCubit الاتنين يسمعوا `watchLibrary()`، فأي إضافة تظهر في الاتنين لوحدها.
- <b>الـ state لازم تبقى immutable وبتتقارن صح:</b> لو بتعمل emit لـ list وعدّلت فيها نفسها، الـ Cubit ممكن مايعرفش إن في تغيير. اعمل list جديدة دايمًا، واستخدم equatable أو freezed للـ states اللي فيها بيانات.

<Note kind="interview" title="سؤال interview">

«إزاي تمنع race condition في البحث؟» debounce يقلل الطلبات، وrequest id بيتزود مع كل طلب، وأي نتيجة الـ id بتاعها مش الأحدث بتتجاهل. ولو عايز توفّر bandwidth، تلغي الطلب نفسه في الـ data layer.

</Note>


</Level>

<LessonPart title="قبل وبعد والكود">

### البحث في Cubit بـ debounce وتجاهل النتائج القديمة

الـ debounce بيقلل عدد الطلبات، والـ request id بيضمن إن نتيجة بحث قديم بطيئة ماتغطيش على الجديدة. الـ Cubit مايعرفش dio، فالإلغاء الحقيقي للطلب (لو احتجته) مكانه الـ data layer.

```dart
class CatalogSearchCubit extends Cubit<CatalogSearchState> {
  CatalogSearchCubit(this._searchBooks) : super(const SearchIdle());

  final SearchBooks _searchBooks;
  Timer? _debounce;
  int _latestRequest = 0;

  void queryChanged(String input) {
    _debounce?.cancel();
    final query = input.trim();
    if (query.length < 2) {
      _latestRequest++; // any in-flight result becomes stale
      emit(const SearchIdle());
      return;
    }
    _debounce = Timer(
      const Duration(milliseconds: 350),
      () => _search(query),
    );
  }

  Future<void> _search(String query) async {
    final requestId = ++_latestRequest;
    emit(const SearchLoading());
    final result = await _searchBooks(SearchParams(query: query, page: 1));
    if (isClosed || requestId != _latestRequest) return; // stale result
    emit(switch (result) {
      Success(:final value) => SearchLoaded(value),
      Err(:final failure) => SearchError(failure),
    });
  }

  @override
  Future<void> close() {
    _debounce?.cancel();
    return super.close();
  }
}
```

<Diagram name="d-46c4268a8c">

المستخدم كتب «flu» ووقف، فالبحث الأول اتبعت بعد 350ms. بعدها كمّل «flutter». الطلب التاني رجع الأول واتعرض، ولما الطلب الأول البطيء رجع، الـ request id بتاعه كان قديم فاتجاهل. من غير الـ id، كانت نتايج «flu» هتمسح نتايج «flutter».

</Diagram>
