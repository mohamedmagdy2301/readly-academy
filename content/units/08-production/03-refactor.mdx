<Level n="1" title="الفكرة بتشبيه">

<Analogy title="تجديد البيت وانت ساكن فيه">

عايز تجدد شقتك، بس مش هتسيبها وتأجّر حتة تانية ست شهور. فبتجددها <b>أوضة أوضة</b>: تفضّي المطبخ، وتجدده، وترجع تطبخ فيه، وبعدين تبدأ في الحمام. وفي كل يوم البيت لسه بيتسكن: في سرير تنام عليه وحنفية شغالة. وقبل ما تكسر أي حيطة، بتصوّر مكان المواسير والكهربا، عشان تتأكد إن مفيش حاجة كانت شغالة وقفت بعد التجديد.

</Analogy>

الـ refactor بنفس الطريقة. عندك feature قديمة شغالة عند المستخدمين، والفريق لازم يفضل يسلّم features جديدة، فماينفعش توقف كل حاجة وتكتبها من الأول. بتنقلها حتة حتة، وفي آخر كل حتة الـ app شغال زي ما كان بالظبط. والصور اللي بتاخدها قبل التكسير هي تستات بتمسك اللي الكود بيعمله النهارده، قبل ما تلمس أي سطر.


</Level>

<Level n="2" title="الكود الأساسي">

feature الـ notes في Readly اتكتبت بسرعة قبل ما المعمارية تتحط، وشكلها كده:

<CodeBlock label="نقطة البداية: كل حاجة في widget واحد">

```dart
// notes/note.dart: the model knows the JSON
class Note {
  const Note({required this.id, required this.text, required this.createdAt});
  final String id;
  final String text;
  final DateTime createdAt;

  factory Note.fromJson(Map<String, dynamic> json) => Note(
        id: json['id'] as String,
        text: json['text'] as String,
        createdAt: DateTime.parse(json['createdAt'] as String),
      );
}

// notes/notes_screen.dart
class _NotesScreenState extends State<NotesScreen> {
  final _dio = getIt<Dio>();
  List<Note> _notes = [];
  bool _loading = true;
  bool _saving = false;
  String? _error;

  @override
  void initState() {
    super.initState();
    _load();
  }

  Future<void> _load() async {
    try {
      final res = await _dio.get<List<dynamic>>('/books/${widget.bookId}/notes');
      final notes = res.data!
          .map((e) => Note.fromJson(e as Map<String, dynamic>))
          .toList()
        ..sort((a, b) => b.createdAt.compareTo(a.createdAt)); // newest first
      setState(() {
        _notes = notes;
        _loading = false;
      });
    } catch (e) {
      setState(() {
        _error = 'Something went wrong';
        _loading = false;
      });
    }
  }

  Future<void> _add(String text) async {
    final trimmed = text.trim();
    if (trimmed.isEmpty || _saving) return; // a business rule and a double-tap guard
    setState(() => _saving = true);
    try {
      final res = await _dio.post<Map<String, dynamic>>(
        '/books/${widget.bookId}/notes',
        data: {'text': trimmed},
      );
      setState(() => _notes.insert(0, Note.fromJson(res.data!)));
      notesChanged.value++; // a global: the book page reloads its notes count
    } catch (e) {
      if (mounted) {
        ScaffoldMessenger.of(context)
            .showSnackBar(const SnackBar(content: Text('Something went wrong')));
      }
    } finally {
      if (mounted) setState(() => _saving = false);
    }
  }

  // build(): a spinner, the error text, or the list with a NoteInput(onSubmit: _add)
}
```

</CodeBlock>

كل اللي الكورس قال إنه بيبوظ موجود هنا: الشاشة عارفة dio والـ URLs وشكل الـ JSON، وقاعدة «الملاحظة الفاضية ماتتبعتش» مستخبية في الـ UI، وكل الأخطاء بقت «Something went wrong». بس الكود ده <b>شغال</b> عند المستخدمين، وده أهم حاجة لازم تفضل صح.

أول خطوة مش إنك تعمل فولدر domain. أول خطوة <b>characterization test</b>: تست بيوصف اللي الكود بيعمله النهارده، مش اللي المفروض يعمله. ولازم يكلّم الحاجات اللي مش هتتغير طول الـ refactor بس: الشاشة من بره (نصوص وزراير)، والشبكة من تحت.

الشبكة بنبدّلها بـ fake على مستوى الـ <b>HttpClientAdapter</b>، زي تست الـ AuthInterceptor في درس الاختبارات. ده الجزء في dio اللي بيبعت الطلب فعلًا، ولو حطيت مكانه fake، كل الطلبات بترجع منه، والكود اللي فوق (سواء widget أو repository) مايحسّش بفرق.

```dart
class FakeNotesApi implements HttpClientAdapter {
  final notes = <Map<String, dynamic>>[
    {'id': 'n1', 'text': 'old', 'createdAt': '2026-01-01T10:00:00Z'},
    {'id': 'n2', 'text': 'new', 'createdAt': '2026-03-01T10:00:00Z'},
  ];
  final posted = <Object?>[];

  @override
  Future<ResponseBody> fetch(
    RequestOptions options,
    Stream<Uint8List>? requestStream,
    Future<void>? cancelFuture,
  ) async {
    if (options.method == 'POST') {
      posted.add(options.data);
      final text = (options.data as Map<String, dynamic>)['text'];
      return _json({'id': 'n3', 'text': text, 'createdAt': '2026-10-04T10:00:00Z'}, 201);
    }
    return _json(notes, 200);
  }

  ResponseBody _json(Object body, int status) => ResponseBody.fromString(
        jsonEncode(body),
        status,
        headers: {Headers.contentTypeHeader: [Headers.jsonContentType]},
      );

  @override
  void close({bool force = false}) {}
}

void main() {
  late FakeNotesApi api;

  setUp(() async {
    await getIt.reset();
    api = FakeNotesApi();
    getIt.registerSingleton<Dio>(
        Dio(BaseOptions(baseUrl: 'https://test'))..httpClientAdapter = api);
  });

  Future<void> pumpNotes(WidgetTester tester) async {
    await tester.pumpWidget(MaterialApp(
      localizationsDelegates: AppLocalizations.localizationsDelegates,
      supportedLocales: AppLocalizations.supportedLocales,
      home: const NotesScreen(bookId: 'OL1'),
    ));
    await tester.pumpAndSettle();
  }

  testWidgets('shows notes newest first', (tester) async {
    await pumpNotes(tester);
    final newY = tester.getTopLeft(find.text('new')).dy;
    final oldY = tester.getTopLeft(find.text('old')).dy;
    expect(newY, lessThan(oldY));
  });

  testWidgets('does not send a blank note', (tester) async {
    await pumpNotes(tester);
    await tester.enterText(find.byType(TextField), '   ');
    await tester.tap(find.byKey(const Key('addNote')));
    await tester.pumpAndSettle();
    expect(api.posted, isEmpty);
  });

  testWidgets('a new note shows on top', (tester) async {
    await pumpNotes(tester);
    await tester.enterText(find.byType(TextField), ' first idea ');
    await tester.tap(find.byKey(const Key('addNote')));
    await tester.pumpAndSettle();
    expect(api.posted.single, {'text': 'first idea'});
    expect(tester.getTopLeft(find.text('first idea')).dy,
        lessThan(tester.getTopLeft(find.text('new')).dy));
  });
```

### PR 1: الشاشة بتكلّم dio بنفسها

طول ما الشاشة هي اللي بتبعت الطلب وبتعمل parse، مفيش حاجة تقدر تحطها بينها وبين الشبكة: لا Cubit ولا fake في التست. فأول حاجة تطلّع الكلام مع الشبكة ورا <b>repository بـ contract</b>، والشاشة تفضل StatefulWidget بـ setState زي ما هي:

<CodeBlock label="الـ repository ورا interface">

```dart
// notes/domain/notes_repository.dart
abstract interface class NotesRepository {
  Future<Result<List<Note>>> getNotes(String bookId);
  Future<Result<Note>> addNote(String bookId, String text);
}

// notes/data/notes_remote_source.dart
class NotesRemoteSource {
  NotesRemoteSource(this._dio);
  final Dio _dio;

  Future<List<Note>> fetchNotes(String bookId) async {
    final res = await _dio.get<List<dynamic>>('/books/$bookId/notes');
    return res.data!.map((e) => Note.fromJson(e as Map<String, dynamic>)).toList();
  }

  Future<Note> addNote(String bookId, String text) async {
    final res = await _dio.post<Map<String, dynamic>>(
      '/books/$bookId/notes',
      data: {'text': text},
    );
    return Note.fromJson(res.data!);
  }
}

// notes/data/notes_repository_impl.dart
class NotesRepositoryImpl implements NotesRepository {
  NotesRepositoryImpl(this._remote, this._logger);

  final NotesRemoteSource _remote;
  final AppLogger _logger;

  @override
  Future<Result<List<Note>>> getNotes(String bookId) => guard(
        () async => (await _remote.fetchNotes(bookId))
          ..sort((a, b) => b.createdAt.compareTo(a.createdAt)), // newest first
        logger: _logger,
        operation: 'notes.getNotes',
      );

  @override
  Future<Result<Note>> addNote(String bookId, String text) => guard(
        () => _remote.addNote(bookId, text),
        logger: _logger,
        operation: 'notes.addNote',
      );
}
```

### PR 2: الـ state متفرقة على 4 متغيرات

`_notes` و`_loading` و`_saving` و`_error` ممكن يبقوا في حالة مالهاش معنى، زي loading وerror مع بعض، ومفيش طريقة تختبر الـ logic من غير ما تعمل pump للشاشة. والسبب إن الـ state مش مكتوبة في مكان واحد كأنواع. الحل Cubit بـ sealed states، والشاشة الجديدة بتتبني <b>جنب</b> القديمة مش مكانها:

<CodeBlock label="NotesCubit">

```dart
sealed class NotesState {
  const NotesState();
}
final class NotesLoading extends NotesState {
  const NotesLoading();
}
final class NotesLoaded extends NotesState {
  const NotesLoaded(this.notes, {this.saving = false, this.addFailure});
  final List<Note> notes;
  final bool saving;
  final Failure? addFailure; // the list stays, a snackbar shows it
}
final class NotesError extends NotesState {
  const NotesError(this.failure);
  final Failure failure;
}

class NotesCubit extends Cubit<NotesState> {
  NotesCubit(this._repository) : super(const NotesLoading());

  final NotesRepository _repository;
  late String _bookId;

  Future<void> load(String bookId) async {
    _bookId = bookId;
    emit(const NotesLoading());
    final result = await _repository.getNotes(bookId);
    if (isClosed) return;
    emit(switch (result) {
      Success(:final value) => NotesLoaded(value),
      Err(:final failure) => NotesError(failure),
    });
  }

  Future<void> add(String text) async {
    final current = state;
    final trimmed = text.trim();
    if (current is! NotesLoaded || current.saving || trimmed.isEmpty) return;
    emit(NotesLoaded(current.notes, saving: true));
    final result = await _repository.addNote(_bookId, trimmed);
    if (isClosed) return;
    emit(switch (result) {
      Success(:final value) => NotesLoaded([value, ...current.notes]),
      Err(:final failure) => NotesLoaded(current.notes, addFailure: failure),
    });
  }
}
```

</CodeBlock>

### الـ global اللي شاشات تانية بتسمع عليه

أول ما الـ flag اتشغّل، صفحة الكتاب بطّلت تحدّث عدد الملاحظات. السبب السطر ده في الشاشة القديمة: `notesChanged.value++`. ده `ValueNotifier` global، وصفحة الكتاب والـ badge في الرئيسية بيسمعوا عليه، والـ NotesView الجديدة مابتلمسوش. والـ characterization test مامسكش ده، لأنه بيختبر شاشة الملاحظات بس.

الحل الغلط إن الـ Cubit يعمل `notesChanged.value++`، كده الكود الجديد ورث المشكلة القديمة. الحل إن الـ repository يقول «حصل تغيير» بـ stream، زي `onCleared` بتاع الـ TokenStore، و<b>كوبري واحد</b> في الـ composition root يوصّله للـ global:

<CodeBlock label="الـ repository بيطلّع تغييراته">

```dart
abstract interface class NotesRepository {
  Future<Result<List<Note>>> getNotes(String bookId);
  Future<Result<Note>> addNote(String bookId, String text);
  Stream<void> get changes; // a note was added
}

class NotesRepositoryImpl implements NotesRepository {
  // ...
  final _changes = StreamController<void>.broadcast();

  @override
  Stream<void> get changes => _changes.stream;

  @override
  Future<Result<Note>> addNote(String bookId, String text) async {
    final result = await guard(
      () => _remote.addNote(bookId, text),
      logger: _logger,
      operation: 'notes.addNote',

    if (result is Success<Note>) _changes.add(null);
    return result;
  }
}
```

</CodeBlock>

- <b>الكود الجديد مايلمسوش:</b> لا الـ Cubit ولا الـ repository يعرفوا إن في global. السطر الوحيد اللي يعرف العالمين في الـ DI، فمسحه بعدين سطر واحد.

الـ global بيفضل عايش لحد ما آخر واحد بيقرا منه يتنقل، والكوبري بس هو اللي يعرفه.

### PR 3: القاعدة جوه الـ Cubit

«الملاحظة الفاضية ماتتبعتش» قاعدة business، بس هي في الـ `add` بتاع الـ Cubit. لو صفحة الكتاب زوّدت زرار «ملاحظة سريعة» بـ Cubit تاني، القاعدة هتتنسخ. فدي اللي تستاهل <b>use case</b>:

<CodeBlock label="AddNote">

```dart
class AddNoteParams {
  const AddNoteParams({required this.bookId, required this.text});
  final String bookId;
  final String text;
}

class AddNote {
  AddNote(this._notes);
  final NotesRepository _notes;

  Future<Result<Note>> call(AddNoteParams params) async {
    final text = params.text.trim();
    if (text.isEmpty) return const Err(ValidationFailure('Empty note'));
    return _notes.addNote(params.bookId, text);
  }
}
```

</CodeBlock>

<CodeBlock label="الـ Cubit بعد الـ use case">

```dart
NotesCubit(this._repository, this._addNote) : super(const NotesLoading());

final NotesRepository _repository; // load() still uses it: getNotes has no rule
final AddNote _addNote;

Future<void> add(String text) async {
  final current = state;
  if (current is! NotesLoaded || current.saving) return;
  emit(NotesLoaded(current.notes, saving: true));
  final result = await _addNote(AddNoteParams(bookId: _bookId, text: text));
  if (isClosed) return;
  emit(switch (result) {
    Success(:final value) => NotesLoaded([value, ...current.notes]),
    Err(failure: ValidationFailure()) => current, // blank: nothing happens, as before
    Err(:final failure) => NotesLoaded(current.notes, addFailure: failure),
  });
}
```

</CodeBlock>

- <b>مفيش GetNotes:</b> هيبقى pass-through بينادي `getNotes` وبس، فالـ Cubit بيكلّم الـ repository مباشرة، زي قرار الـ pass-through في درس الـ Domain. الـ use case بيتعمل لما في قاعدة يحميها، مش عشان الفولدر يبقى كامل.
- <b>الـ ValidationFailure بترجّع نفس الـ state:</b> الشاشة القديمة كانت بتتجاهل الملاحظة الفاضية من غير رسالة، والـ refactor بيحافظ على ده. لو عايز رسالة، ده تغيير سلوك وليه PR لوحده.
- <b>ده نفس AddNote اللي في درس SOLID:</b> لما يحتاج يتأكد إن الكتاب موجود في المكتبة، هياخد `BookLookup` زي هناك.

القاعدة بقت في مكان واحد وبتتختبر بـ dart test، والـ use case اتعمل للعملية اللي فيها قاعدة بس.

### PR 4: الـ Note لسه عارف شكل الـ JSON

الـ contract في الـ domain بيرجّع Note فيه `fromJson`، يعني الـ domain مربوط بشكل الـ API. لو السيرفر غيّر `createdAt` لـ `created_at`، التعديل هيلمس class بيستخدمها الـ Cubit والـ use case. ده بالظبط درس الـ Data: الـ entity تبقى Dart صافي، والـ JSON يروح DTO بـ mapper:

<CodeBlock label="الـ entity والـ DTO">

```dart
// notes/domain/note.dart: no JSON
class Note {
  const Note({required this.id, required this.text, required this.createdAt});
  final String id;
  final String text;
  final DateTime createdAt;
}

class NoteDto {
```

الـ flag بقاله أسبوعين `true` في prod ومفيش مشاكل. لو سبت الشاشة القديمة، حد هيصلّح bug فيها هي، أو هيعمل import ليها في feature جديدة. والـ refactor مابيخلصش غير لما القديم يتمسح:

<Level n="4" title="قرارات الـ senior">

- <b>امتى ماتعملش refactor أصلًا:</b> feature محدش بيلمسها ومابتطلّعش bugs. الكود الوحش اللي مابيتغيرش مابيكلّفش حاجة. ولا feature هتتشال قريب. ابدأ بالملفات اللي بتتعدّل أكتر وفيها bugs أكتر، وده بيبان من الـ git log ومن Sentry.
- <b>refactor مش rewrite:</b> إعادة الكتابة من الصفر بتوقف الـ features شهور، وبتضيّع سلوكيات صغيرة محدش كتبها في أي حتة، زي «الأحدث الأول»، ومابتوصلش للمستخدم غير في الآخر. الخطوات الصغيرة بتوصل كل أسبوع، وكل واحدة تقدر ترجع فيها.
- <b>إقناع الفريق بالأرقام مش بالذوق:</b> «الكود وحش» مش حجة. «آخر 3 تعديلات في الـ notes خدوا ضعف التقدير، و40% من الـ bugs من الشاشة دي، ومفيش عليها ولا تست» حجة. واعرضه كـ PRs صغيرة بتمشي جنب الـ features، مثلًا 20% من كل sprint، مش sprint متوقف.
- <b>التقدير لكل PR:</b> ماتقدّرش «الـ refactor كله». أول feature بتاخد أطول لأنها بتبني الأساس (الـ `registerNotes` والـ characterization tests والـ flag)، واللي بعدها أسرع. ولو PR عدّى يومين شغل، قسّمه.
- <b>قيس التقدم بأداة:</b> architecture test بيقرا الـ imports، وبيفشل لو أي ملف جديد بره الـ data عمل import لـ dio. الملفات القديمة في allowlist، والتست بيفشل كمان لو ملف اتصلّح ولسه في الليست، فالليست مابتصغرش غير لتحت. وطولها هو رقم التقدم اللي بتوريه للفريق.

- <b>الـ ADR قبل أول PR:</b> بيقول ليه بتنقل الـ notes، والترتيب، والـ flag، وامتى القديم يتمسح، وإن أي feature جديدة بتتكتب بالشكل الجديد من النهارده. من غيره، حد جديد في الفريق هيقلّد الشاشة القديمة لأنها أول حاجة شافها.
- <b>تغيير السلوك PR لوحده:</b> لو لقيت bug وانت بتعمل refactor، اكتبه وصلّحه في PR منفصل فيه تست بيوصف السلوك الجديد. لو اتخلطوا، الـ review مش هيفرّق بين اللي اتنقل واللي اتغير، ولو حصلت مشكلة مش هتعرف ترجع أنهي واحد.

<Note kind="interview" title="سؤال interview">

«عندك feature قديمة كلها في widget واحد. هتنقلها لـ Clean إزاي من غير ما توقف الشغل؟» أبدأ بـ characterization tests بتكلّم الشاشة من بره والشبكة بـ fake `HttpClientAdapter`، فتفضل خضرا طول الطريق. بعدين PRs صغيرة، كل واحد بيطلع للمستخدمين لوحده: الـ repository ورا contract، وبعدين Cubit في شاشة جديدة جنب القديمة ورا flag، وuse case بس للعملية اللي فيها قاعدة، وبعدين الـ entity للـ domain والـ JSON لـ DTO، وفي الآخر أمسح القديم والـ flag. أي global مشترك بيفضل لحد ما آخر قاري يتنقل، وكوبري واحد في الـ composition root بيوصّله. والتقدم بقيسه بـ architecture test على الـ imports وallowlist بتصغر بس، والقرار كله مكتوب في ADR. والأهم: الـ refactor مابيغيّرش سلوك، وأي تصليح PR لوحده.
