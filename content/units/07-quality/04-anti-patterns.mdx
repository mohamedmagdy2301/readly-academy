دي أشهر الأخطاء اللي بتظهر في مشاريع Clean Arch في Flutter، وهستخدمها وأنا بعمل review لكودك.

| الخطأ | المشكلة | البديل |
| --- | --- | --- |
| الـ Model بيعمل extends للـ Entity | الـ domain بيترتبط بشكل الـ JSON، وأي تغيير في الـ API بيوصل للـ UI | DTO منفصل مع mapper صريح |
| الـ Repository بيرجع DTO | نفس المشكلة بس أسوأ | الـ contract بيرجع entities بس |
| الـ Failure كـ String أو class عادية | مفيش exhaustive handling، والـ UI بتعمل if على نصوص | هرم Failures بـ sealed classes |
| use case pass-through لكل method | boilerplate بيخلي الناس تكره المعمارية | قرار فريق واضح: إما تسيبه وانت واعي ليه، أو الـ Cubit يكلّم الـ repository مباشرة لما مفيش logic |
| استدعاء get_it جوه الـ widgets والـ Cubits | الـ dependencies مخفية والتست صعب | constructor injection، وget_it في الـ composition root بس |
| الـ Cubit بيعرف Dio أو بيعمل parse لـ JSON | الـ presentation عرفت تفاصيل الـ data | الـ Cubit يكلّم use case أو repository contract |
| try/catch في كل طبقة أو ابتلاع الأخطاء | الأخطاء بتتوه ومفيش logging | تحويل واحد عند الحد (guard) مع log |
| feature بتعمل import لـ internals feature تانية | الـ features بتتشابك ومتنفعش تتشال | public API (barrel) أو contract في core |
| الـ core بقى مكان أي حاجة مشتركة | god package، وأي تغيير فيه بيعيد build كل حاجة | core صغير، والحاجة اللي بتخدم featureين بس تفضل في واحدة منهم |
| الـ side effects جوه build | الـ navigation أو الـ snackbar بيتكرر مع كل rebuild | BlocListener |
