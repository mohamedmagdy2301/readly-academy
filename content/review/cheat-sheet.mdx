كل قاعدة في سطر. ارجعله قبل أي مشروع جديد أو interview.

<CheatGrid>

<CheatCard title="Domain">

- مفيش Flutter ولا dio ولا json.
- الـ entities والـ value objects جواها قواعدها.
- الـ contracts بترجع entities وResult.
- use case بس لما في logic حقيقي.

</CheatCard>

<CheatCard title="Data">

- DTO منفصل مع mapper صريح.
- الـ data source بيرمي exceptions.
- الـ repository هو الحد: guard واحد.
- الـ DB هي مصدر الحقيقة الوحيد.
- retry للطلبات الـ idempotent بس.

</CheatCard>

<CheatCard title="Presentation">

- الـ Cubit مايعرفش الـ data layer.
- الـ states كلها sealed مع exhaustive switch.
- أي async محمي: debounce وrequest id وflag.
- الـ side effects في BlocListener.
- الـ Failure بيتترجم هنا بـ l10n.

</CheatCard>

<CheatCard title="التوصيل (wiring)">

- constructor injection دايمًا.
- get_it في الـ composition root بس.
- factory للـ Cubits، وsingleton للـ repositories.
- flavors بـ entry points منفصلة.
- كل feature ليها barrel هو الـ public API.

</CheatCard>

<CheatCard title="SOLID">

- S: سبب واحد للتغيير لكل class.
- O: ضيف قطعة، ماتفتحش الكود الشغال.
- L: نفس الـ contract tests على كل implementation.
- I: interface صغير على قد اللي بيستخدمه.
- D: الـ domain بيعرّف الـ interface، والـ data بتنفّذه.

</CheatCard>

<CheatCard title="الاختبارات">

- الـ domain بتغطية 100%.
- الـ repository: تست لكل نوع Failure.
- blocTest لكل سيناريو في الـ Cubit.
- golden بالعربي والـ dark mode.
- integration للـ flow الحرج بس.
- fake للسلوك، mock للتفاعل والحالات الغريبة.
- مفيش `DateTime.now` ولا `Future.delayed` حقيقي في تست: Clock وfake_async.
- كل bug بيبدأ بتست فاشل.

</CheatCard>

<CheatCard title="الـ API والأخطاء">

- الـ status فئة، والـ code تفصيلة، والـ message للـ logs.
- الـ guard هو الحد الوحيد، وبيمسك أنواع معينة بس.
- الـ JSON الغلط Failure مش crash: `parseOrThrow`.
- الخطأ مايمسحش البيانات اللي على الشاشة.
- «حاول تاني» بس لما الإعادة ممكن تفرق.
- الـ API بيتغير additive بس، والـ app tolerant reader.

</CheatCard>

<CheatCard title="Dart Async والـ Streams">

- الـ async بيحل الانتظار، مش الحساب: الشغل التقيل لـ `Isolate.run`.
- كل Future ليه صاحب: `await` أو `.wait` أو `unawaited` بقصد.
- الـ Futures اللي شغالة مع بعض تتستنى مع بعض: `.wait`.
- الـ `timeout` والـ `eagerError` بيوقّفوا الانتظار، مش الشغل.
- كل `listen` جنبه field، وكل field جنبه `cancel` في `close`.
- `switchMap` للبحث، و`exhaustMap` للحفظ، و`asyncMap` للي لازم يتعمل كله.
- `distinct` على ليست محتاج `ListEquality`.

</CheatCard>

<CheatCard title="Cubit وBloc">

- Cubit default، وBloc لما الـ inputs بتتزاحم وكل نوع محتاج سياسة.
- الـ state immutable وبتتقارن بالقيمة: Equatable أو freezed أو sealed.
- sealed لو كل حالة شاشة، وstatus لو البيانات بتفضل.
- `isClosed` بعد كل await في الـ Cubit.
- `create` للي الـ widget صاحبته، و`.value` للموجود.
- `read` في الـ callbacks، و`watch` و`select` في build.
- الـ Cubit مايعرفش Flutter ولا Cubit تاني.
- الـ transformer لكل `on<E>` لوحده، والـ default `concurrent`.

</CheatCard>


<CheatCard title="Riverpod">

- الـ domain والـ data مايعرفوش Riverpod، وتست بيحرس ده.
- `watch` في build، و`read` في الـ callbacks.
- الـ repositories `keepAlive`، والشاشات autoDispose.
- كل provider بيرجّع الـ contract، مش الـ Impl.
- الفلتر اللي بيغيّر النتايج family parameter.
- بعد أي await: `ref.mounted`، أو ref الـ build لو ممكن يتعاد.
- التست بـ `ProviderContainer.test` والـ override للـ repository.

</CheatCard>

<CheatCard title="Real-time والخلفية">

- الـ socket data source بيكتب في drift، والشاشة بتقرا من drift.
- الـ event إشارة، والحقيقة في الـ API.
- كل reconnect بـ backoff وjitter، وبعده catch-up بالـ cursor.
- الكتابة من السيرفر مشروطة: مفيش تعديل محلي، والـ version أكبر.
- الحذف بيسيب tombstone.
- الـ push إشارة، والإشعار بيفتح link من allowlist.
- الخلفية بونص، والضمان في الـ foreground.

</CheatCard>

<CheatCard title="الـ Performance">

- مفيش optimization من غير رقم قبله ورقم بعده.
- القياس في profile mode على جهاز متوسط بس.
- اعرف الـ frame الأحمر في الـ UI ولا الـ raster قبل ما تصلّح.
- الـ listening في أوطى widget محتاجه، بـ `select`.
- ليستة طويلة: scroll واحد وslivers، من غير `shrinkWrap`.
- الصورة تتفك بالمقاس اللي هيتعرض.
- كل حاجة ليها dispose بتتعملها dispose.
- الـ DI lazy، والـ constructors مابتعملش شغل.

</CheatCard>

<CheatCard title="الـ Packages">

- قسّم لما المشكلة موجودة فعلًا، وبالأرقام.
- بالـ features، مش بالطبقات.
- فك الدواير وانت لسه فولدرات.
- الـ pubspec هو الحد، وتست بيقرا الـ pubspecs.
- `depend_on_referenced_packages` كـ error.
- B محتاجة حاجة من A: interface في B وA تنفّذه.
- الـ CI على اللي اتغير وكل اللي بيعتمد عليه.

</CheatCard>

<CheatCard title="الـ Design System والـ Accessibility">

- الشاشات بتستخدم أدوار، مش ألوان ولا أرقام.
- اللي ناقص من الـ ColorScheme في ThemeExtension.
- الـ `if` الوحيد على الـ dark جوه دالة الثيم.
- start وend، مش left وright.
- النص الجاي من data بيتلف بـ bidi isolate.
- كل حاجة بتتداس ليها label وtarget 48×48.
- مفيش ارتفاع ثابت حوالين نص، والخط 200% بيتست.

</CheatCard>

<CheatCard title="الأمان والـ flags">

- أي secret في الـ binary مش سر.
- الـ tokens في الـ secure storage، والـ logout بيمسح كل حاجة.
- الـ logs والـ Sentry مافيهمش بيانات المستخدم.
- الـ pinning قرار من الـ threat model، وعلى الـ CA مش الشهادة.
- الـ release flag الـ fallback بتاعه off، والـ kill switch on.
- الـ flags بتتقرا عند الفتح، والـ kill switches بس لحظية.
- كل release flag ليه تاريخ مسح.

</CheatCard>

</CheatGrid>
